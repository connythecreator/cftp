## How this is measured

- cftp, scp, SFTP, HTTPS, FTP, and HTTP run on the same machine over loopback, so no network bottleneck hides protocol differences. The release gate runs them in one Docker container with local sshd, vsftpd, and nginx servers.
- cftp, scp, and SFTP upload a whole tree over one connection; FTP, HTTP, and HTTPS upload each file with a separate `curl` process. HTTP and HTTPS use nginx with `dav_methods PUT` and `create_full_put_path`; HTTPS adds TLS 1.3 with a certificate that curl verifies.
- Datasets are deterministic pseudo-random bytes. They are intentionally incompressible, so the comparison does not credit cftp for zstd compression. Source trees and logs compress better and usually transfer faster.
- Each row is the median of the configured iterations. Verification happens after the timer stops. Every run uploads to a fresh destination.
- The release gate requires cftp to be within 25.0% of the fastest security-equivalent peer (scp, SFTP, HTTPS) on every dataset. A run with a missing peer fails the gate.
- FTP and HTTP are plaintext: they encrypt nothing and verify no integrity. They are published as reference points for the same hardware and are excluded from the gate, because a kernel-to-file plaintext copy is not a fair comparison for an encrypted, integrity-checked protocol.
